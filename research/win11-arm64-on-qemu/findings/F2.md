# F2: Existing ready-made projects, scripts and forks that run or install Windows on ARM under QEMU, with concrete reusable configurations.

## Findings

### [1] jeremyd2019/winautoconfig 公开的 TCG 命令行是这套生态里唯一写清「纯模拟」参数的现成配置：`-M virt,virtualization=true` + `-accel tcg,thread=multi` + `-m 4096` + `-smp 6` + `-cpu cortex-a72`，其余全是 stock `-M virt` 选项（ramfb / qemu-xhci / usb-tablet / usb-kbd / nvme / pflash / usb-storage 光驱 / virtio-net user）；KVM 与 TCG 的差异只有三处（`-M virt` 去掉 `,virtualization=true`、`-accel kvm`、`-cpu max`），且不修补 ACPI、不加 Windows 专用设备描述。
- quote: "-M virt,virtualization=true"
- url: https://github.com/jeremyd2019/winautoconfig/wiki/Windows-ARM64-VMs-with-QEMU
- source_type: primary
- published: 2024-11-15（wiki 页面最后修订，共 4 版）
- confidence: high

### [2] 同一页面声称 Windows ARM64 在 KVM 与 TCG 下都跑得动，并给 Windows 11 24H2 标注了更新的 CPU 型号 `cortex-a710`（而非长期沿用的 `cortex-a72`），暗示新版 Windows 内核要求更高的 ISA 基线——PocketVM 固定用的 `cortex-a76` 介于两者之间。
- quote: "Windows ARM64 runs reasonably well in QEMU, both under KVM (on Linux ARM64 host) and TCG."
- url: https://github.com/jeremyd2019/winautoconfig/wiki/Windows-ARM64-VMs-with-QEMU
- source_type: primary
- published: 2024-11-15
- confidence: high

### [3] winautoconfig 用分立 pflash 对 `AAVMF_CODE.ms.fd`（`if=pflash,index=0,readonly=on`）+ `AAVMF_VARS.ms.fd`（`index=1` 可写），取自 Debian sid 的 `qemu-efi-aarch64` 2021.08-1 包并称 QEMU 自带固件「相当过时」；因为要挂 virtio 驱动必须进 edk2 UI 关 Secure Boot，引导也不是 bootindex 而是人工选盘（Esc → `Device Manager`→`Secure Boot Configuration` 取消 `Attempt Secure Boot` → 分辨率改 1024x768 → `Boot Manager` 选 NVMe 项）。
- quote: "Note that in order to use the virtio drivers, Secure Boot needs to be disabled in the \"BIOS\"."
- url: https://github.com/jeremyd2019/winautoconfig/wiki/Windows-ARM64-VMs-with-QEMU
- source_type: primary
- published: 2024-11-15
- confidence: high

### [4] winautoconfig 的 TCG 路线把系统盘挂在 `nvme` 控制器上（而非 virtio-blk），因此完全不需要注入存储驱动；对照 Vogtinator 的 virtio-blk 路线必须在安装时手动从 virtio-win ISO 的 `E:\viostor\w11\ARM64` 载入驱动。PocketVM 选 NVMe 与这条实战路线一致。
- quote: "-device nvme,drive=NVME1,serial=nvme-1"
- url: https://github.com/jeremyd2019/winautoconfig/wiki/Windows-ARM64-VMs-with-QEMU
- source_type: primary
- published: 2024-11-15
- confidence: high

### [5] Vogtinator 的 gist 是目前最新的官方 ISO 路线（2024-12 起微软才放出官方 ARM64 安装 ISO，`Win11_24H2_EnglishInternational_Arm64.iso` 已验证可用）：用 QEMU 自带 `/usr/share/qemu/qemu-uefi-aarch64.bin` 作 `-bios`，不虚拟化的宿主上把 `-cpu host -accel kvm` 换成 `-cpu neoverse-n1`（比 `-cpu max` 更快），显示用 `ramfb` + `virtio-gpu-pci` 并列，两个 ISO 都走 `usb-storage`，系统盘用 virtio-blk。
- quote: "replace `-cpu host -accel kvm` with `-cpu neoverse-n1`"
- url: https://gist.github.com/Vogtinator/293c4f90c5e92838f7e72610725905fd
- source_type: primary
- published: 2024-12 起持续更新
- confidence: high

### [6] Vogtinator 全程不使用 TPM：安装界面 Shift-F10 → regedit 在 `HKLM\SYSTEM\Setup` 下建 `LabConfig` 键写三个 DWORD 绕过 TPM/Secure Boot 检查；同时记录了三个非显然陷阱——QEMU 默认 MAC 会与某些 AutoPilot 注册设备假匹配 UUID、导致被强制登录域；自 build 25931 起安装阶段必须提供网络；收尾用 `oobe\bypassnro` 绕开微软账户（另：装机在「Installing 42%」卡 >30 分钟属预期）。
- quote: "The default QEMU MAC address will result in a false UUID match with some AutoPilot enrolled devices"
- url: https://gist.github.com/Vogtinator/293c4f90c5e92838f7e72610725905fd
- source_type: primary
- published: 2024-12 起
- confidence: high

### [7] raspiduino/waq 不装系统而是分发预装镜像（Windows 10 ARM64 build 17134，源自 Pi64 论坛帖，已预修 EFI、禁用 pagefile/搜索索引/打印服务）：pflash 对 `QEMU_EFI.img`/`QEMU_VARS.img`、`-cpu cortex-a72`、`-smp 3`、`-m 2048`、`--accel tcg,thread=multi`、`-device VGA`、`nec-usb-xhci`+`usb-kbd`/`usb-mouse`，系统盘经 `usb-storage,drive=boot` 挂载，从 UEFI Boot Manager 选 `UEFI QEMU QEMU HARDDRIVE` 引导；作者实测 TCG 装机要 3–4 天，README 直接让需要新版本的人去看 Vogtinator 的 gist，并建议真要可用就去买树莓派（他另开 raspiduino/sm-a600g-kvm 走手机 KVM）——即「Android 上可用」被认为依赖 virtualization 而非 TCG。
- quote: "about 3 -> 4 days on my machine"
- url: https://github.com/raspiduino/waq
- source_type: primary
- published: README 自述停在 2022；仓库最后 push 2024-01-14（12 commits、102★、13 forks）
- confidence: high

### [8] dockur/windows-arm 是这条链路上最成熟的「成品」（2.3k★、240 forks、688 commits，MIT）：Windows 11 ARM64 Pro/LTSC/Enterprise/Tiny11 自动下载 + 无人值守安装；显示默认 `ramfb`（因为它不需要额外图形驱动），`virtio-gpu` 只在装完后手动切且安装阶段会黑屏；但硬性要求 `/dev/kvm`，即不支持纯 TCG。
- quote: "By default, the `ramfb` adapter is used as it doesn't require any additional graphics drivers."
- url: https://github.com/dockur/windows-arm
- source_type: primary
- published: 2026-10 读到（同作者 x64 版 dockur/windows 为 53.7k★/975 commits）
- confidence: high

### [9] fenio/wharf 是 2026-06 的新方案，走 `qemu-system-aarch64 -accel hvf` + dockur 式自动化：wimlib 把 virtio 驱动注入 ISO 并重建 UDF、autounattend 跳过 OOBE、默认装 OpenSSH 供 CI，`USE_TPM=Y` 时启用 swtpm 模拟的 TPM 2.0；其安装监督器会「自动从安装中途重启时偶发的 edk2 固件挂起中恢复（重启整个 QEMU 进程即可清除）」——工程解法是重启进程而非调参数。
- quote: "auto-recovers from the intermittent edk2 firmware hang on mid-install reboots"
- url: https://github.com/fenio/wharf
- source_type: primary
- published: 仓库创建 2026-06-19，最后 push 2026-06-20（13 commits、2★、MIT）
- confidence: medium

### [10] 同一来源指出 Windows 10 ARM 挂在 QEMU 的 aarch64 固件下，且「HVF 与 TCG 都复现」，归因到 Win10 引导程序 vs `virt` 机器的 EDK2 构建（`ConvertPages: failed to find range`）——这是「加速器无关的 Windows-ARM-on-QEMU 启动失败」的独立实例，与 PocketVM 观察到换 CPU/固件/加速器都不改变结局同型。
- quote: "hangs in QEMU's aarch64 firmware on Apple silicon"
- url: https://github.com/fenio/wharf
- source_type: primary
- published: 2026-06
- confidence: medium

### [11] 上游 QEMU issue #2893 截至检索时仍开放：M4 Mac mini + QEMU 9.3.2 + `-machine virt,highmem=on -cpu host -smp 4 -m 8G -accel hvf` + `edk2-aarch64-code.fd` pflash + `virtio-gpu-pci` + `qemu-xhci` + `virtio-net`，Windows 11 ARM64 ISO 进 EFI 后直接挂住，串口打印固件的 `failed to find range` 类错误。
- quote: "the error convertprogress failed to find range errors"
- url: https://gitlab.com/qemu-project/qemu/-/issues/2893
- source_type: primary
- published: unknown（基于 QEMU 9.3.2、macOS 15.3.2）
- confidence: high

### [12] UTM 官方 Windows 11 指南的门槛是版本与核数而非设备参数：构建号必须 ≥21390，否则安装器直接 BSOD `SYSTEM_THREAD_EXCEPTION_NOT_HANDLED`；Windows 安装至少需要 2 个核；新版 UTM 自动开 Secure Boot + TPM（也可在 QEMU 设置里手开 TPM 2.0）；Win11 24H2 与 UTM guest-tools 图形驱动不兼容会黑屏（需先弹出 guest ISO 才能进安装器）；`OOBE\BYPASSNRO` 已被微软封堵，改从 Shift+F10 执行 `start ms-cxh:localonly`。
- quote: "The build number should be 21390 or higher."
- url: https://docs.getutm.app/guides/windows/
- source_type: primary
- published: unknown（站点当前版本，含 Win11 24H2 条目）
- confidence: high

## Dead ends

- Bing（含 `setmkt=en-US`）对本主题完全无用于检索：返回 Windows/ISO 下载页聚合与镜像站教程，引号限定词被忽略。
- `html.duckduckgo.com`、`lite.duckduckgo.com`、`raw.githubusercontent.com`、`gist.github.com`：本机 webfetch 全部 DNS/传输失败（SSRF 保护），GitHub 原文一律改走 github.com 渲染页与 api.github.com。
- 本会话工具面里没有 Browser Use/cua_repl，websearch skill 的「SERP + 结果页」路径不可用；检索实际由 GitHub 仓库搜索 API（`api.github.com/search/repositories?q=windows+arm64+qemu`，41 个结果）代替。
- 该 API 结果中 `exusxt/ARM64onX86`（描述正是「在 x86 PC 上跑 Windows 11 ARM64 VM」）仅 1 字节、是空壳；`Xachaeus/WinPi64`、`FinleyTheDachshund/windows-10-for-arm64-Chromebook-qemu-xml-code`、`MohammadAlnawateer/windows-11-arm-utm-lab`、`Br0des/WinPocket`、`ZuTM`、`burrow`、`MacDow`、`erictan2001/QArmDroid` 均为 0–39★ 的同类包装（且多为 macOS/HVF 或 Virtualization.framework 路线），未提供比上述来源更具体的配置，故未引用。
- 未找到任何现成方案提供 Windows on ARM 专用的 ACPI 表或 `virt` 机器设备描述补丁；所有被读到的方案都只改 CPU 型号、固件构建与设备选择。
- 未验证：UTM 的 QEMU 后端（非 Virtualize 路径）装 Win11 ARM 的具体设备清单与 TPM 配置——`docs.getutm.app` 的 QEMU 设置页未取。
